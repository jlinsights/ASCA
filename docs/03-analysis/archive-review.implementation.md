# 관리자 아카이브 검토 — 벤치마크 적용 다음 단계

## 동작

- `/admin/archive/reviews`: 검토 중·게시된 작품 목록과 페이지 이동.
- 상세 화면: 작품 정보, 비공개 웹용 미리보기, 검토 의견과 처리 이력.
- 수정 요청·반려: 사유 필수. 작품을 비공개 초안으로 돌려보내며 소유자의
  `/archive/my`에 수정 사유를 표시한다.
- 게시 승인: 공개 작가 프로필과 필수 작품 정보·사진 경로를 확인한 뒤 썸네일과
  웹용 파생 이미지만 공개 버킷으로 복사한다. 이미지 경로 변경과 게시 상태 확정은
  하나의 DB 트랜잭션으로 처리한다. 원본과 연결 이력의 인증 여부는 바꾸지 않는다.
- 비공개 전환: 사유 필수. DB 공개 조회를 먼저 차단하고 공개용 파일을 회수한 뒤
  비공개 이미지 경로로 되돌린다. 실패하면 검토 중 상태를 유지하고 재시도한다.

## 권한과 저장

Clerk의 검증된 주 이메일에 따른 기존 관리자 권한을 서버 페이지와 API 양쪽에서
검사한다. 로그인·권한 검사 전에 service_role 조회나 미리보기 서명을 하지 않는다.
API는 출처·요청 크기·속도 제한과 SecurityMiddleware 검사를 수행한다.

`archive_reviews`는 클라이언트 접근이 금지된 처리 원장이다. 검토자 Clerk ID,
사유, 이미지 작업 목록, 처리 상태와 완료 시각을 기록한다. 소유자에게는 반려
사유만 선별해서 전달한다. 두 업무 전용 RPC 역시 service_role만 실행할 수 있다.
임의 SQL 실행 기능이나 작가 본인 쓰기 RLS 정책은 추가하지 않는다.

웹용 미리보기 서명은 짧게 만료되며 원본 링크는 만들지 않는다. 게시 시 생성한
공개 파일의 cache-control은 0으로 설정한다. 공개 파일을 지워도 사용자가 이미
다운로드한 사본까지 회수할 수는 없다.

## 동시 요청과 실패 복구

작품 행 잠금, 클라이언트의 수정 시각, 작품별 미완료 작업 유일성으로 충돌을
제어한다. 같은 operation ID로 재시도하면 완료 여부를 먼저 확인한다. 중단된
processing 작업은 서버 실행 제한보다 긴 유예 시간 후 회수할 수 있다. 재시도마다
임대 토큰과 공개 파일 경로를 바꾸고 이전 경로 정리 목록을 보존한다. 이전 요청은
새 토큰으로 확정할 수 없고, 이전 파일 정리가 새 게시 파일을 지우지 않는다.

복사 실패 시 부분 파일을 정리한 뒤 실패 상태를 기록한다. 최종 DB 확정의 응답이
유실되면 파일을 임의 삭제하지 않고 원장에서 완료 여부를 재확인한다. 프로세스가
강제 종료되어 정리하지 못한 경로는 원장에 남아 다음 재시도에서 처리된다.
게시·회수는 Storage와 DB 사이의 분산 트랜잭션이 아니므로 미완료 작업의 재시도와
확인이 필요하다. 회수 실패를 성공으로 표시하지 않는다.

## 배포 순서와 검증

`20261018000500_archive_review_workflow.sql`을 적용한 뒤 앱을 배포해야 한다. 이
마이그레이션은 이번 구현 과정에서 운영 DB에 적용하지 않았다. 기존 Airtable
동기화와 공개 테이블 정책은 변경하지 않는다. 롤백은 처리 원장을 보존하는 후속
마이그레이션으로 한다. 미완료 이미지 작업을 먼저 마무리하고 공개 파일 상태를
확인한 뒤 앱을 되돌려야 한다.

로컬 검증 명령:

```sh
node --conditions=react-server --import tsx scripts/test-archive-reviews.mjs
node scripts/test-archive-upgrade.mjs
npm run type-check
npm run lint
npm run test -- --runInBand
node scripts/build-archive-local.mjs
```

검토 통합 스크립트는 별도 임시 로컬 DB를 만들고 전체 마이그레이션을 재생한다.
권한, 상태 전환, 중복 요청, 임대 만료·이전 요청 차단, 이미지 경로 복원을 검사한
뒤 실제 로컬 Storage에서 공개용 복사·회수와 원본 비공개도 확인하고 자신이 만든
임시 DB·파일만 제거한다. Storage 실패와 확정 응답 유실은 서비스 단위 테스트로
검사한다. 실제 관리자 계정으로 미리보기·게시·회수를 수행하는 브라우저 검증은
별도로 필요하다.

## 후속 범위

이력 인증을 위한 별도 근거 검토, 게시본과 수정본의 분리, 사진 교체·재정렬, 검토
알림 발송은 이번 범위에 포함하지 않는다. 게시된 작품의 작가 직접 수정은 계속
차단한다.

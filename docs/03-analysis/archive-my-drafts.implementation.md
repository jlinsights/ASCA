# 내 작품·초안 수정 — 벤치마크 적용 1단계

## 구현 범위

- `/archive/my`: Clerk 로그인 후 연결된 작가의 작품만 조회한다. 상태와 페이지
  이동을 제공한다.
- `/archive/my/[id]`: 소유한 초안의 작품 정보를 불러와 수정하거나 검토를
  요청한다.
- `PATCH /api/archive/drafts/[id]`: 서버 소유권 검사 후 service_role로 변경한다.
- 소유권은 클라이언트의 artist ID 대신 DB의 Clerk 계정 연결에서 확인한다.
  관리자도 개인 작업 공간에서는 자신의 연결 프로필만 조회·수정한다.
- 초안 상태와 `updated_at`을 UPDATE 조건에 포함해 검토 시작 후 변경 및 오래 열린
  창의 덮어쓰기를 차단한다. 충돌·저장 실패 시 입력은 유지한다.
- 게시·인증·소유권·이미지 경로는 요청 본문에 허용하지 않는다.
- 기존 사진과 연결 이력은 유지한다. 이미지 업로드나 새 작품 생성 없이 정보를
  수정한다.
- 한국어·영어·일본어·번체 중국어 문구를 제공하고 기존 Ink System 토큰을
  사용한다.

## 검증과 한계

소유권 거부, 비로그인·교차 출처 거부, 게시·인증 위조 차단, 상태 및 수정 시각
충돌, 초안 값 복원, 실패 시 입력 유지, 목록 상태별 수정 링크를 테스트한다. 실제
Clerk 계정으로 저장하는 브라우저 검증은 별도로 필요하다.

이번 단계에서는 사진 교체·삭제·재정렬, 연결 이력 정정, 작성 중 불완전한 신규
폼의 자동 저장을 구현하지 않는다. 기존 필수 항목 검증은 유지한다. 검토 중·게시된
작품은 수정할 수 없으며, 공개 파생 이미지와 원본 저장 정책을 변경하지 않는다. DB
마이그레이션과 운영 데이터 변경은 없다.

## 다음 단계

관리자 검토·반려·게시 흐름을 구현한다. 게시 및 비공개 전환은 공개 이미지의
복사·회수와 함께 처리해야 하며, 상태만 바꾸는 구현을 사용하지 않는다. 게시 후
수정은 승인된 공개본과 수정 초안을 분리하는 계약부터 확정한다.

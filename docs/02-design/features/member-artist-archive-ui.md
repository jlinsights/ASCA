# 회원 작가 아카이브 — 시안 대조와 후속 UI

## 기준과 화면

사용자 제공 `ASCA_docs_archive.zip`의 v0.2 기획서와 시안은
[원본 자료](./member-archive-reference/README.md)에 보관한다. 시안의
인명·작품·숫자는 모두 가상이므로 앱 데이터로 옮기지 않는다. 실제 DB 계약은
[DB 기반 문서](../../member-artist-archive.md)와 PR #76을 따른다.

화면 구성·작품 비율·좌측 프로필·등록 단계는 시안을 참고한다. 색과 글꼴은
[DESIGN.md](../DESIGN.md)의 Ink System을 따른다. 시안의 빨강 CTA·폰트·배경값으로
브랜드 토큰을 변경하지 않는다.

## 구현 경로

- `/archive`: 서버 검색·서체/등급 필터·페이지 구분·작품 썸네일 카드·빈 상태
- `/archive/artists/[id]`: 아카이브 프로필·공개 작품·수상/전시 이력 페이지
- `/archive/artworks/[id]`: 비율 보존 이미지·석문/풀이·출전·작품 연결 이력
- `/archive/submit`: 사진 → 작품 정보 → 석문/영문 → 이력의 등록 화면
- `POST /api/archive/submissions`: Clerk 소유권/관리자 검증 후 비공개 등록

공개 읽기는 anon 클라이언트로 RLS를 유지하며 컬럼을 명시한다. 연락처·소유자 ID·
original_path는 공개 DTO에 포함하지 않는다. 신규 쿼리가 실패하면 오류 화면을
표시하고 샘플 작가·작품으로 대체하지 않는다. 검색은 쿼리 문법 문자를 제거한다.
목록과 프로필 작품/이력은 서버 페이지 구분으로 PostgREST 행 제한을 피한다.

## 등록의 보안·운영 계약

- 로그인만으로 작가를 만들거나 계정을 연결하지 않는다. 연결된 프로필이 없는 경우
  협회에 연결을 요청하도록 안내한다. 관리자는 서버에서 검증된 기본 이메일과
  ADMIN 이상 역할로 판정하며, 화면에는 등록 가능한 작가 ID·이름만 전달한다.
- 관리자 선택 목록은 이름순 최초 100명이다. 대규모 대리 등록에는 별도 작가
  검색이 필요하다. 현재 목록에 없는 작가의 요청을 만들거나 우회한 것으로
  표시하지 않는다.
- JPEG/PNG/WebP 사진 최대 3장, 합계 3MB. Vercel 요청 크기 제한에 맞춘 1단계
  업로드 제한이다. 3000px 원본·대용량 분할/직접 업로드는 후속 작업이며 시안 권장
  크기를 이번 업로드가 보장하지 않는다. 서버는 실제 디코딩·픽셀 제한·포맷을
  검사하고 WebP 웹/썸네일을 생성한다. Supabase 이미지 변환은 사용하지 않는다.
- 모든 파일은 무작위 작품 UUID 하위의 비공개 버킷에 저장한다. 요청 본문의 작가
  ID는 DB 소유자와 대조하며 created_by·상태·인증 값을 임의로 신뢰하지 않는다.
  미인증 이력만 생성한다. 원본 키·서명 URL·개인 연락처는 응답하지 않는다.
- Origin 검사·계정별 요청 제한·접근 거부/변경 감사 기록을 적용한다. 저장 실패 시
  이번에 생성한 행과 객체만 보상 삭제한다. 네트워크 단절 중 보상 삭제까지
  실패하면 UUID로 남은 비공개 행/파일을 운영자가 확인해야 한다. DB/Storage 간
  원자적 트랜잭션은 아니며 장애 복구 큐·멱등 요청 토큰은 후속 작업이다.
- 저장 성공 시 중복 제출을 막고 초안/검토 상태를 명확히 안내한다. 초안 재편집·
  내 작품 관리·관리자 승인·게시/게시취소와 public 사본 수명주기는 아직 구현하지
  않았다. 따라서 이번 UI는 공개 조회와 신규 비공개 등록까지의 범위다.
- 게시 전 private 파생본을 public으로 복사해야 공개 화면의 경로가 유효하다. DB
  status만 수동 변경해도 업로드 이미지가 자동 공개되지는 않는다.
- 한국어·영어·일본어·번체중국어 UI 번역을 통합 표에 등록한다. 실제 DB 콘텐츠가
  한국어만 있으면 그대로 표시하고 번역을 만들어 내지 않는다.

## 배포

운영 DB에 아카이브 마이그레이션을 적용하지 않았다. 이 UI 브랜치는 DB PR #76을
기반으로 하며 독립적인 후속 검토 대상으로 둔다. 운영 적용·main 병합은 하지
않는다. DB와 앱의 배포 순서는 DB 문서의 주의사항을 따른다. Supabase cloud
Preview가 비활성화되어 있으면 Vercel Preview만으로 DB 동작을 검증했다고 표시하지
않는다.

## 검증 명령

```bash
npm run pre-commit -- -- --runInBand
node --conditions=react-server --import tsx scripts/test-archive-ui.mjs
node scripts/build-archive-local.mjs
```

공개 조회 통합 검증은 실제 로컬 DB의 임시 작가·작품·이력을 사용하고 종료 시
삭제한다. 업로드 라우트 테스트는 Clerk와 DB를 모의하여 소유권 거부·상태 위조
거부· 실제 이미지 디코딩/파생본 생성·실패 정리를 검증한다. 실제 Clerk 세션으로
로그인한 브라우저의 제출 검증을 대신하지 않는다.
